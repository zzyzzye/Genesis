# 用户余额与上游实账

登录用户可以使用影音助手、生图、生视频和 `/toolbox/svg`。博客写作台和博客管理工具仍只允许站长使用。新用户余额为零，由站长人工充值；当前没有在线支付或自动赠送额度。

## 金额与调用规则

数据库用整数保存人民币，一单位等于 `0.00000001` 元；API 金额为八位小数字符串。钱包写入先锁用户行，在同一事务中创建订单、消费报价并冻结余额。流水只通过新增记录表达充值、冻结、结算、解冻和退款，不能通过管理 API 编辑原始凭证。删除作品、对话或生成结果不会删除账务凭证；部署前的任务不补扣。

MiMo 和 SVG 免费，共享普通用户最多一个运行任务的限制，每次输出最多 4096 token。普通用户每轮 Agent 共用最多八次模型请求的预算，子调用使用同一归属；付费模型关闭 SDK 隐式重试。站长免余额限制，标题单独记入站点成本。

付费模型必须有管理员核验后的价格版本。审核填写单个请求的最高费用、请求体字节上限、输出上限和额度换算。最高费用必须涵盖该模型所有允许的数量、尺寸、时长、缓存、阶梯价格和附加费用；请求体大小仅是输入边界，不能代替供应商的 Token 或媒体定价。Agent 冻结单请求最高费用的八倍，图片和视频冻结一次请求上限。未审核、渠道不支持实账或已暂停的模型仍可展示，普通用户不能付费提交。不要使用猜测的图片、视频价格开放模型。

报价有效期五分钟，绑定用户、模型、业务参数和价格版本。用户确认最大冻结金额后，客户端携带 `quote_id` 和稳定任务标识提交。实际消费低于冻结金额时返还差额；超过冻结金额时用户扣费封顶，差额归站点承担，并暂停模型新付费调用。

## YYAPI 对账

HTTP 发送前持久化调用归属；响应头到达即记录 `x-oneapi-request-id`，正文 `resp_…` 不用作对账键。后台按配置渠道请求 `/api/log/token`，只按网关请求 ID 精确匹配。渠道指纹包括连接及 Key，配置变化不会把另一渠道的账单用于旧订单。

费用来自 `other.billing_formula.final_quota`，缺失时使用顶层结算 `quota`，不使用零值占位的 `model_price` 或 `model_ratio`。保存阶梯、缓存、倍率和模型映射证据，`expr_b64` 仅展示存证，不执行。样例核验：`126 / 500000 = 0.000252` 元。500000 是当前已核验 YYAPI 样例的每元额度，新渠道必须单独确认。

消费记录类型为 2，退款为 6，参照 [New API 日志定义](https://github.com/QuantumNous/new-api/blob/main/model/log.go)。仅在退款能精确关联原网关请求且未处理时新增退款流水；不能关联的供应商退款需要人工核对，不能按金额或时间猜测。

请求尚未发送即可解冻。发送后失败、取消、超时、没有正文、下载保存失败都不能直接视为免费。账单未出现时保留冻结并退避重试；多次未匹配转为“需核对”，服务重启继续处理。结果保存重试沿用既有响应，不能再提交生成。近期接口之外的历史缺失记录由站长凭供应商证据核对，不能自动结算为零。

## 操作入口

- `/account/wallet`：可用余额、冻结金额、分页流水与生成账单、请求明细。
- `/account/billing`：站长搜索账号、确认金额与备注后人工入账，审核模型费用上限，核对异常。负数人工入账为可用余额更正，不允许扣成负余额。操作标识保存在当前标签页会话中，响应未知时沿用原标识重试；刷新后仍需人工确认。
- `/toolbox/svg`：固定服务端 MiMo，复用 AI 任务、SSE、停止和恢复。源码完成后校验 XML，再由 DOMPurify 清理，使用 Blob 图片预览。脚本、事件属性、foreignObject、样式和外部资源不会进入预览、复制及下载；三者使用同一安全结果。无效或截断内容保留源码并显示错误，不自动重试。

接口统一使用 `/api/v1`：`/billing/wallet`、`/billing/entries`、`/billing/operations`、`/billing/operations/{id}`、`POST /billing/quotes`；管理接口为 `/admin/billing/users`、`/credits`、`/policies`、`/operations` 和 `/operations/{id}/resolve`。用户只可读自己的凭证，管理接口只允许站长。人工核对必须保留理由和操作者，不能抹掉已匹配实账；供应商差异退款或余额更正另记凭证。

## 发布顺序与验证边界

1. 先对数据库执行 Alembic 迁移至 `20261026_26`，再发布服务端和前端。`25` 建立账务表，`26` 绑定价格审核渠道。复用项目既有 Docker Compose 与端口。
2. 生产密钥由部署者自行配置。新版本没有默认付费价格策略，也不执行充值。
3. 先用站长调用核验目标渠道的响应头、账单可见性、额度换算和全部参数价格上限，再在账务管理启用精确模型的审核版本。审核绑定当时的域名与 Key 指纹，换渠道后必须重新审核；缺少核验换算的站点调用保持待核对，不默认套用其他渠道费率。图片与视频必须分别核验，不沿用文本模型定价。
4. 用小额人工充值账户验证冻结、延迟实账、差额退回与异常；核对通过后再开放对应模型。未通过审核的模型保持禁止普通用户付费提交。

自动化测试使用脱敏账单、合成身份与隔离数据库，包含精度、幂等、越权、真实 PostgreSQL 并发冻结、超额封顶、延迟账单与退款。浏览器验收使用当前 Compose 前端上的合成接口响应，不充值真实账户，不产生真实模型费用。本次没有进行生产部署，也没有据此宣称图片、视频的生产实账适配已经核验。
