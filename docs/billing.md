# 用户余额与上游实账

登录用户可以使用影音助手、生图、生视频和 `/toolbox/svg`。博客写作台和博客管理工具仍只允许站长使用。新用户余额为零，由站长人工充值；当前没有在线支付或自动赠送额度。

注册用户时在同一事务创建钱包，可用余额和冻结金额均为 `0.00000000`。开发账号初始化也补齐缺失的钱包；迁移 `20261027_28` 为已有用户补齐钱包，不覆盖原余额，也不生成零元流水。没有交易的新用户应看到零余额及空流水、空账单，而不是缺少钱包记录。

个人账单仅包含本人的免费和付费创作。自动标题等站点承担的操作保留在管理员账务中，不出现在个人账单列表和明细接口中。

2026-10-27 普通用户真实验收：通过注册页面创建专用成员，确认数据库存在零余额钱包、页面显示零余额及空记录；按用户授权人工入账 ¥0.50。Grok 4.5 两次真实请求均被上游 HTTP 429 拒绝，每次冻结 ¥0.407888，核对为零费用后全部解冻。最终可用 ¥0.50、冻结 ¥0、消费 ¥0，充值、冻结及解冻流水完整。已验证失败后的资金恢复，成功生成后的真实实扣仍需上游通道可用时验收。

## 金额与调用规则

数据库金额统一使用 `NUMERIC(20,8)` 保存人民币元，Python 全程使用 `Decimal`，API 继续传八位小数字符串。例如数据库 `available = 5.00000000` 就是五元。上游原始 `quota` 和 `quota_per_cny` 仍是整数额度，不与人民币金额混用。钱包写入先锁用户行，在同一事务中创建订单、消费报价并冻结余额。流水只通过新增记录表达充值、冻结、结算、解冻和退款，不能通过管理 API 编辑原始凭证。删除作品、对话或生成结果不会删除账务凭证；部署前的任务不补扣。

`20261027_27` 同步转换钱包、冻结、流水、订单、上游消费金额和旧报价快照，保留原标识与实际价值；价格字段改为 `max_request_amount`，上游消费金额改为 `amount`。隔离 PostgreSQL 测试验证升级、降级、最小金额及负流水往返无损。

MiMo 和 SVG 免费，共享普通用户最多一个运行任务的限制，每次输出最多 4096 token。普通用户每轮 Agent 共用最多八次模型请求的预算，子调用使用同一归属；付费模型关闭 SDK 隐式重试。站长免余额限制，标题单独记入站点成本。

付费模型必须有管理员核验后的价格版本。审核填写单个请求的最高费用、请求体字节上限、输出上限和额度换算。最高费用必须涵盖该模型所有允许的数量、尺寸、时长、缓存、阶梯价格和附加费用；请求体大小仅是输入边界，不能代替供应商的 Token 或媒体定价。Agent 冻结单请求最高费用的八倍，图片和视频冻结一次请求上限。未审核、渠道不支持实账或已暂停的模型仍可展示，普通用户不能付费提交。不要使用猜测的图片、视频价格开放模型。

报价有效期五分钟，绑定用户、模型、业务参数和价格版本。用户确认最大冻结金额后，客户端携带 `quote_id` 和稳定任务标识提交。实际消费低于冻结金额时返还差额；超过冻结金额时用户扣费封顶，差额归站点承担，并暂停模型新付费调用。

## 模型单价预览

模型目录的 `pricing` 字段提供只读价格预览，不自动开放付费模型，也不替代实际账单结算。自行配置 `GENESIS_YYAPI_ACCESS_TOKEN`（YYAPI 控制台访问令牌）；站点要求用户 ID 时配置 `GENESIS_YYAPI_USER_ID`。控制台地址 `GENESIS_YYAPI_CONTROL_BASE_URL` 默认 `https://www.yyapi.cloud`。

服务读取全部 `/api/token/` 分页，将已有渠道 Key 去掉 `sk-` 后的前四位、后四位与脱敏 Key 唯一匹配得到分组，再结合 `/api/pricing` 的允许分组及分组倍率，通过 `/api/status` 确认币种与换算。重复匹配、分页不完整、令牌失效、自动分组或倍率缺失均返回无法预览。凭据和脱敏 Key 不返回前端；成功结果缓存 60 秒。

本地如需代理，可自行设置 `GENESIS_YYAPI_PROXY_URL=http://host.docker.internal:7897`；该项仅用于控制台价格查询，生产环境留空直连。修改 Compose 环境配置后需重新创建后端容器，源码热更新不会刷新容器环境。

预览支持普通 Token 比率及可静态核验的线性阶梯表达式，Decimal 金额以字符串返回。输入、输出与缓存价按百万 Token 展示；复杂函数、无法确认的条件和图片/视频计价不执行表达式，也不显示为零。样例 `codex-pro` 倍率 0.2，Luna 短档输入/输出 ¥0.4/¥2.4，长档 ¥0.8/¥3.6。

模型选项悬停、键盘聚焦或触屏点选展示详情；搜索旁刷新按钮重新加载模型和价格。未配置或查询失败仍保留模型列表，并说明原因。

2026-10-27 实时核验：个人访问令牌可读取令牌目录与定价；本地容器请求未设置代理时通过。GPT 的 `codex-pro`、Claude 的 `kiro-aws` 和 Grok 的 `grok` 分组匹配成功；Grok 使用严格小于 200,000 Token 的分档，达到边界进入长档。Gemini 当前渠道所属分组未出现在返回的价格表中，继续显示价格不可核验。上述结果不代表生产服务器网络已经验证，也未开放新的付费策略。

## YYAPI 对账

HTTP 发送前持久化调用归属；响应头到达即记录 `x-oneapi-request-id`，正文 `resp_…` 不用作对账键。后台按配置渠道请求 `/api/log/token`，只按网关请求 ID 精确匹配。渠道指纹包括连接及 Key，配置变化不会把另一渠道的账单用于旧订单。

费用来自 `other.billing_formula.final_quota`，缺失时使用顶层结算 `quota`，不使用零值占位的 `model_price` 或 `model_ratio`。保存阶梯、缓存、倍率和模型映射证据，`expr_b64` 仅展示存证，不执行。样例核验：`126 / 500000 = 0.000252` 元。500000 是当前已核验 YYAPI 样例的每元额度，新渠道必须单独确认。

消费记录类型为 2，退款为 6，参照 [New API 日志定义](https://github.com/QuantumNous/new-api/blob/main/model/log.go)。仅在退款能精确关联原网关请求且未处理时新增退款流水；不能关联的供应商退款需要人工核对，不能按金额或时间猜测。

请求尚未发送即可解冻。发送后失败、取消、超时、没有正文、下载保存失败都不能直接视为免费。账单未出现时保留冻结并退避重试；多次未匹配转为“需核对”，服务重启继续处理。结果保存重试沿用既有响应，不能再提交生成。近期接口之外的历史缺失记录由站长凭供应商证据核对，不能自动结算为零。

错误账单 `type=5` 只有在网关请求 ID 精确匹配且结算额度明确为零时，才结算为零并退回冻结；错误账单额度非零或缺少费用字段仍保留待核对。2026-10-27 的两次授权实测均遇到上游 429，供应商实账均确认零费用，已核验冻结及全额退回；测试者随后停止真实调用，未将其报告为正数实扣验证通过。Decimal 迁移后的全量 518 项测试、Ruff、格式及 mypy 通过，覆盖率 91.28%；保留框架标题序列化的既有警告。

## 操作入口

### 配置普通用户的聊天价格策略

部署者可通过现有后端容器执行只读审核：

```bash
docker compose --env-file .env.development -f compose.yml exec -T backend python -m genesis_api.billing.chat_policies
```

报告列出单请求上限、整轮最大冻结及未通过核验的型号。确认后，在同一命令末尾加 `--apply`，复用管理员审核入口追加价格版本及审计流水，不充值任何用户。生产使用 `.env.production` 和 `compose.prod.yml`，需在实际生产容器单独执行，不随服务启动自动启用。相同价格和渠道重复执行不会重复记账；已因超额暂停的旧版本不会被同一版本重新启用。

审核要求当前 Key 的 `/api/log/token` 存在可解析消费账单，站点额度口径与已核验的每元 500,000 一致，人民币价格完整且模型有明确输入窗口。冻结使用整个模型输入窗口、各分档最高费率及全部缓存项目的保守上界，输出最多 4,096 Token，额外覆盖供应商额度舍入，再乘每轮最多八次请求。字节上限单独限制请求体，不替代 Token 窗口。缺少能力上限、价格或渠道账单的模型保持关闭。付费 HTTP 发送边界核验模型、地址、单份输出及输出上限，不允许子调用换模型或启用未计价的供应商内置工具。

Grok 4.5、4.7 当前整轮最多冻结 ¥0.407888，适合用 ¥0.50 余额验收；GPT、Claude 的完整窗口和缓存上界会导致更高冻结，必须以报价框为准。管理员可为经过单独核验的更严格参数范围建立新版本，不按短提示的预估消费降低通用上限。真实充值由站长手动完成，真实调用由测试者执行。测试前后的可用、冻结、消费和流水必须一致，不能把合成测试通过当成已完成真实用户实扣。

2026-10-27 本地配置：已启用 14 个有完整价格、输入上限及可解析实账来源的聊天策略。全量 499 项后端测试通过，覆盖真实 DeepAgents/LangChain 流式 HTTP 经请求钩子记录、延迟账单结算、重试不重复记账、子调用改模型及输出超限拦截；Ruff、格式和 mypy 通过。上游生成响应使用合成数据，未替用户充值或发起真实付费调用；生产需要单独审核及用户实扣验收。

- `/account/wallet`：可用余额、冻结金额、分页流水与生成账单、请求明细。
- `/account/billing`：站长搜索账号、确认金额与备注后人工入账，审核模型费用上限，核对异常。负数人工入账为可用余额更正，不允许扣成负余额。操作标识保存在当前标签页会话中，响应未知时沿用原标识重试；刷新后仍需人工确认。
- `/toolbox/svg`：固定服务端 MiMo，复用 AI 任务、SSE、停止和恢复。源码完成后校验 XML，再由 DOMPurify 清理，使用 Blob 图片预览。脚本、事件属性、foreignObject、样式和外部资源不会进入预览、复制及下载；三者使用同一安全结果。无效或截断内容保留源码并显示错误，不自动重试。

接口统一使用 `/api/v1`：`/billing/wallet`、`/billing/entries`、`/billing/operations`、`/billing/operations/{id}`、`POST /billing/quotes`；管理接口为 `/admin/billing/users`、`/credits`、`/policies`、`/operations` 和 `/operations/{id}/resolve`。用户只可读自己的凭证，管理接口只允许站长。人工核对必须保留理由和操作者，不能抹掉已匹配实账；供应商差异退款或余额更正另记凭证。

## 发布顺序与验证边界

1. 先执行 `alembic upgrade head`，确认包含 `20261027_28`，再发布服务端和前端。`25` 建立账务表，`26` 绑定价格审核渠道，`27` 将全部金额及历史报价快照由旧最小单位无损换算为人民币元，`28` 为已有用户补齐零余额钱包。金额转换期间暂停旧后端，避免新旧单位混用；不能只在数据库中手动修改字段类型。复用项目既有 Docker Compose 与端口。
2. 生产密钥由部署者自行配置。新版本没有默认付费价格策略，也不执行充值。
3. 先用站长调用核验目标渠道的响应头、账单可见性、额度换算和全部参数价格上限，再在账务管理启用精确模型的审核版本。审核绑定当时的域名与 Key 指纹，换渠道后必须重新审核；缺少核验换算的站点调用保持待核对，不默认套用其他渠道费率。图片与视频必须分别核验，不沿用文本模型定价。
4. 用小额人工充值账户验证冻结、延迟实账、差额退回与异常；核对通过后再开放对应模型。未通过审核的模型保持禁止普通用户付费提交。

自动化测试使用脱敏账单、合成身份与隔离数据库，包含精度、幂等、越权、真实 PostgreSQL 并发冻结、超额封顶、延迟账单与退款。浏览器验收使用当前 Compose 前端上的合成接口响应，不充值真实账户，不产生真实模型费用。本次没有进行生产部署，也没有据此宣称图片、视频的生产实账适配已经核验。
