# 文章 AI 导读

公开文章提供默认收起的「AI 导读」，放在摘要与正文之间，展示三个要点和一句阅读重点。它概括文章内容，不核验作者主张；本阶段不提供公开对话或问答。

## 生成与缓存

- `blog/guide.py` 定义结构化内容、内容指纹和发布事务内的失效规则。人工编辑与博客 Agent 确认写入共用 `apply_post_data`，不会遗漏其中一个入口。
- `blog/agent/prompt.py` 拥有导读提示词；`blog/agent/guide.py` 只领取持久化任务、构造文章快照、校验段落引用和条件提交缓存。
- 模型初始化与结构化调用复用 `genesis_api/agent/runtime.py` 的 `generate_structured` 和 LangChain 原生 `with_structured_output` / `astream`。导读没有业务工具、对话历史和 checkpoint，不调用后台写作 Agent；简单缓存刷新无需建立另一套 Agent 编排。
- 默认文本供应商与模型沿用站点配置，只有已发布的标题、摘要、正文会送入模型。正文按空行分段，模型返回要点对应的段落编号，服务端检查编号存在；这能保留依据位置，不能保证语义或事实正确。正文中的指令只作为数据，不访问链接、附件或作者资料。
- 标题、摘要、正文的 SHA-256 指纹决定版本；分类、标签与阅读时长等元数据变化可复用缓存。生成结果写入独立的 `blog_article_guides` 表，不改变文章的 `updated_at`，避免破坏编辑器并发保护。

应用生命周期启动串行缓存刷新任务，每轮最多为 20 篇无缓存的已发布文章排队，再领取一个任务。PostgreSQL 行锁与 `skip_locked` 防止多进程重复领取；模型调用限制 60 秒，领取超过 120 秒后允许恢复。关闭时取消任务并恢复待处理状态，随后关闭公共运行时。

普通失败保留失败状态，不持续消耗模型调用；作者再次保存已发布文章可重试。未配置模型、空正文、超过 60,000 字符、返回结构或段落编号无效均不影响发布和阅读。日志只保留通用事件和文章 ID，不输出模型异常正文、配置或提示词。

## 公开读取边界

`GET /api/v1/blog/posts/:slug` 返回 `content_revision`；前端展开时调用 `GET /api/v1/blog/posts/:slug/guide?revision=...`，状态为 `pending`、`ready`、`unavailable` 或 `outdated`。公开接口不生成、不排队、不写库，草稿、撤回和不存在均为 404。导读返回普通文本，不执行模型提供的 HTML。

更新文章后旧缓存立即失效；生成任务提交时同时匹配文章 ID、指纹、领取时间、运行状态和仍已发布的条件，迟到结果无法覆盖新任务。撤回发布删除缓存，删除文章通过外键级联清理；重新发布重新生成。

前端默认不请求导读；首次展开读取，成功后在当前文章中复用，切换文章或内容版本重置。等待生成只提供手动重新查看，失败提供读取重试；12 秒读取期限与 AbortController 防止无限等待和迟到响应。正文、代码块与评论始终可独立使用。

## 验证

容器内运行前端 ESLint、TypeScript、Vitest、构建，以及后端 Ruff、mypy、pytest。导读测试覆盖公开读取不能生成、草稿隔离、更新失效、迟到结果、领取恢复、生成失败与取消、缓存命中、应用关闭顺序，以及前端折叠、手动重试、版本重置和读取期限。浏览器检查真实生成结果、加载和异常状态、键盘展开与收起、减少动态效果及桌面和窄屏布局。
