# 博客收录、历史版本与回复通知

## 使用入口

- 搜索与分享：`/robots.txt`、`/sitemap.xml` 自动提供站点规则和公开文章地址。文章初始 HTML 包含标题、摘要、canonical、Open Graph、Twitter Card 和 BlogPosting 结构化数据；站内跳转同步更新。
- 历史版本：文章编辑器 →「历史版本」→ 选择版本比较 →「载入此版本」→ 确认载入 → 核对并保存。载入本身不会写服务器或发布文章。
- 评论回复：登录后，在公开评论下点击「回复」，沿用评论输入区提交并等待审核。被回复者在账户 →「回复通知」查看、标记已读及定位回复。

## 数据与权限

迁移 `20261126_33` 新增文章快照、通知表及评论父级引用。新文章保存时开始记录；既有文章第一次修改会同时记录修改前内容和新内容，不伪造过去的历史。快照只恢复内容、封面、分类、标签、精选与阅读时长，保留当前文章地址、发布状态、发布计划和并发校验版本。已删除分类和标签会跳过。后台、Agent 与导入共用保存入口。

每篇文章的历史仅站长可读，快照不随再次编辑而更改；列表每页 20 条，选中版本才读取正文。历史记录不是独立数据库备份，物理删除文章会级联删除其快照。

回复只能关联同篇文章的公开评论，仍需原有审核。审核公开后为原评论作者创建一条站内通知；自己回复自己不通知，重复审核不重复通知。未审核、隐藏、删除的评论及非公开文章不会通过通知泄露。通知只允许接收者查看和标记已读；此功能不发送邮件或短信。

## 部署

开发环境复用已有 Compose 前后端服务，迁移命令为 `docker compose exec -T backend uv run --no-sync alembic upgrade head`。本次已在开发数据库应用迁移。

生产前端需要随本次更新部署 `frontend/nginx.conf`，通过 SSI 在 HTML 响应中注入实时公开元数据，不能只把生成的静态 index.html 放到不支持 SSI 的托管服务。Nginx 保留公开 Host，并识别上游 HTTPS 协议头；外层代理必须保留公开域名和正确协议。HTML 与元数据使用 no-store，避免撤稿后继续分享旧摘要。元数据不可用时页面仍加载，默认 noindex。

生产构建、Nginx 配置检查和部署在 CI 或服务器执行；本地未执行生产构建，也未部署线上。发布前检查真实域名下的文章 HTML、canonical、分享图片绝对地址、robots 与 sitemap，并确认草稿不出现。外部搜索引擎的实际收录及社交平台缓存更新由对应服务决定。

## 验证范围

后端 `test_blog_reader_features.py` 覆盖公开边界、HTML/JSON 转义、历史权限和冲突、回复关联、审核通知、去重与标记权限。前端 `ArticleHistory.test.tsx`、`BlogNotifications.test.tsx`、`Comments.test.tsx` 覆盖确认载入、失败保留、目标切换和通知状态。

浏览器通过 Compose 页面检查桌面及 390px 布局；账户、历史和写评论使用隔离的测试响应，不向真实文章新增评论或修改内容。初始 HTML 和 sitemap 使用实际开发服务读取。

2026-11-26 验证：后端全量 800 项通过，覆盖率 91.39%；前端全量首次 660 项通过、1 项影音用例超时，该用例单独复测通过，新增收录用例及相关回归亦通过。已检查历史的选择、确认、取消、Escape 焦点恢复、读取失败和空态，通知的未读、已读、失败重试和空态，以及评论回复的输入聚焦、失败保留、重试成功、定位和审核引用上下文。桌面与手机未见内容遮挡或页面横向溢出。生产 Nginx SSI 尚待部署环境验证。
